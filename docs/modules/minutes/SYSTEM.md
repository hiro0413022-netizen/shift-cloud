# 議事録システム（apps/minutes・mtg_*）— 設計の正典

2026-09-27 立ち上げ。ユーザー構想:

- フェーズ1 文字起こし＋要約（ゴルフレッスンのように、場面で要約の型を変える）
- フェーズ2 資料作成（確定した議事録から、モードに合った資料を作る）
- フェーズ3 YOZAN専用LLMサーバー（弁護士など秘密性の高い用途。通常のAIでは機密を守れないため）

フェーズ1は**社内先行**（L1/L2）で作った。外販を見越して `company_id` は全表に持つ。

## いちばん大事な決めごと: 機密レベルは録音の「前」に決め、変えられない

音声や文字起こしを外部AIに送った時点で機密は戻らない。「秘匿の会議だった」と録音後に気づいても手遅れ。
だから **どのAIで処理するか（＝どこにデータが行くか）を会議の作成時に固定**する。

| レベル | 処理する場所 | 見られる人 | 保存 |
|---|---|---|---|
| L1 通常 | Gemini | 会社の `use_minutes` / `view_hq` 全員 | 音声は文字起こし後に即削除 |
| L2 社外秘 | Gemini（**学習に使われない有料API**。`MINUTES_L2_ENABLED=1` で人が確認した印を立てるまで作れない） | 作成者とオーナーだけ | 音声即削除・文字起こしは確定から30日で自動削除（本文は残る） |
| L3 秘匿 | YOZAN専用サーバーのみ（フェーズ3） | 作成者とオーナーだけ | **Supabaseに中身を置かない**（DBのcheck制約） |

守っている仕組み（どれか1つが崩れても他で止まるように重ねてある）:

1. `src/lib/levels.ts` の `providerFor` が**AIの行き先を決める唯一の場所**。L3 は `local` 以外を返さず、サーバー未設定なら投げる（Geminiに落とさない）。テスト `tests/minutes-levels.test.ts`。
2. AIを呼ぶのは `src/lib/ai/router.ts` だけ。画面やAPIから `gemini.ts` を直接 import しない。
3. DB: `mtg_level_immutable` トリガーでレベル変更を拒否。`mtg_l3_no_content_in_cloud` 制約で L3 行に文字起こし・要約・本文を入れられない。
4. RLSは有効化のみでポリシー無し＝ブラウザ（anon/authenticated）から一切読めない。読み書きは service_role で `ownMeeting()` を必ず通す（L2 の閲覧制限はここ1か所）。
5. フェーズ1では L3 の会議はそもそも作れない（`levelStatus`）。

## 要約モード（`src/lib/modes.ts`）

共通の核 = 概要 / 決定事項 / ToDo（担当・期限）/ 未決事項。モードごとに「抜き出す欄」と「書いてはいけないこと」を足す。

| id | 名前 | 主な欄 | 主なルール |
|---|---|---|---|
| general | 社内定例・一般 | 話し合ったこと | 議題ごと |
| contract | 契約・商談 | 条件 / 相手の要望 / こちらの約束 / 未合意 | 金額・日付は発言どおり。双方の了承が無いものは「未合意」 |
| dev | 開発会議 | 決まった仕様 / 採らなかった案と理由 / 課題 / 次に作るもの | 「なぜ」を残す |
| sales | 営業会議 | 案件ごと / 数字 / 打ち手 | 発言に無い見込みを付けない |
| hearing | 顧客ヒアリング | 困りごと / 現状 / 予算感 / 決める人 / 次の一手 | お客様の言葉を言い換えない |
| legal | 法務的会議 | 論点 / リスク / 根拠 / 見解（誰の） / 要確認 | 断定しない・法的評価を加えない |
| lawyer | 弁護士・秘匿（**L3専用**） | 時系列 / 依頼者の主張 / 証拠 / 方針案 / 期限 | 依頼者と弁護士の発言を混ぜない |
| one_on_one | 1on1・面談 | 本人の話 / 合意した目標 / 会社の約束 | 評価・人物像をAIが書かない |

- モードは録音後でも変えて作り直せる（文字起こしから作るので音声は不要）。`auto` はAIが種類を**提案**し、人が変えられる。
- AIが勝手に足した欄は `parseSummary` で捨てる。

## Lesson OS 会話メモから引き継いだ柱

1. **同意が無いと作れない**（`consent_at`）。
2. **音声は文字起こしが済んだ区間から即削除**。失敗した区間の音声は消さない（やり直せるように）。
3. **AIは下書き**（`summary`）。人が確認して確定した `body` / `todos` だけが正式な議事録。
4. **発言を言い換えない**。各項目に根拠の発言 `q` を原文で付けさせ、`verifyQuote` で文字起こしと照合。
   見当たらない項目は赤く出す（`ok` / `near` / `none`）。

## 録音の作り（`app/m/[id]/recorder.tsx`）

- **10分ごとに MediaRecorder を作り直す**＝各区間が単体で読める音声ファイル。継ぎ目は1秒重ねる。
- 区間は録音中から Storage に直接PUT（`minutes-audio` バケット）→ 録音中から文字起こしが進む。
- `/api/transcribe` は**1回に1区間だけ**（300秒制限を超えないため）。前の区間の最後800字を渡して話者表記をそろえる。
- 欠けた区間は黙ってつながず「（この区間は文字起こしできませんでした）」と明記する。
- 持ち込みファイルは50MBまで。18MB超は Gemini Files API に上げ、終わったら消す。
- ブラウザが落ちても失うのは最大10分。送れなかった区間は画面のメモリに残り、再送できる。

## 表と置き場

- `mtg_meetings`（会議）/ `mtg_segments`（区間）— migration `0206_minutes.sql`
- 権限 `use_minutes`（まず 会社オーナー・本部）。現場に広げるときは Shift Cloud `/admin/roles`。
- L2 の30日削除は cron を増やさず、一覧を開いたついでに `purgeExpired`。

## 環境変数

| 名前 | 用途 |
|---|---|
| `GEMINI_API_KEY` | L1/L2 の処理 |
| `MINUTES_L2_ENABLED=1` | そのキーが学習に使われない有料枠だと確認した印（無いとL2を作れない） |
| `MINUTES_MODEL` | モデルの差し替え（既定 gemini-3.5-flash） |
| `LOCAL_LLM_BASE_URL` / `LOCAL_STT_BASE_URL` / `LOCAL_LLM_API_KEY` / `LOCAL_LLM_MODEL` / `LOCAL_STT_MODEL` | フェーズ3のYOZANサーバー（OpenAI互換の口） |

## フェーズ3に向けて残っていること

- L3 の保存先（文字起こし・要約・本文）をYOZANサーバー側に置く。`mtg_meetings` には器（件名・日付・状態）だけ。
- Whisper単体では話者が分からない → サーバー側に話者分離を足す。
- 置き方は2案: A 共用サーバー（安い・中小向け）／B 事務所に小型GPU機を置いてYOZANが保守（最高秘匿）。
  A は「預け先がGoogleからYOZANに移るだけ」なので、秘密保持・再委託禁止の契約、YOZAN社員も中身を見られない運用、第三者監査が要る。

## フェーズ2（資料作成）の候補

契約→条件確認書・合意事項メール／開発→開発依頼キューへ起票／営業→提案書のたたき・次回アジェンダ／
法務・弁護士→論点整理メモ・時系列表／共通→議事録PDF（`/m/[id]/print` は済）・ToDoのLINE配信。
資料作成もフェーズ1と同じ機密レベルの経路に乗せる（L3の議事録からはL3の中でしか作らない）。
