# AIカルテナレッジ 音声メモ ＋ 知識の自己増殖（設計）

作成: 2026-09-03 ／ 対象: `apps/swing-cortex`（販売名 **AIカルテナレッジ**）
位置づけ: **PGA NOTE の補助システム**として外販する。正典は本ファイル。上位は `SYSTEM.md`。

---

## 0. 結論（先に）

1. 「開く → 録音開始 → 検索しながらレッスン → 停止 → コメント生成 → ナレッジへ反映」という流れは **CORTEX に合っている**。lesson-os と違って生徒・動画に紐づけなくてよく、録音1本＝1レッスンで完結する。
2. ただし **「生成内容をナレッジに自動追加」は採用しない**。自動でやるのは **候補を溜めること** までで、ナレッジ本体に入るのは **人が1タップで採用したものだけ**。
3. 候補を昇格させる門は **AIの自己採点ではなく「別の日に3回以上、同じ趣旨で出た」という事実**にする。AIが触れない外側の数字を使う（`docs/genesis/DECISIONS.md` の自律進化の原則と同じ）。
4. 会話メモの実装は **これで2回目**（1回目は lesson-os #179/#201）。モジュール化ルール「2回目で切り出す」に従い、録音・逐次アップロード・音声→要約・音声の自動削除は `packages/` へ出してから CORTEX に載せる。
5. 外販する以上、**録音同意は導入先の店舗ごとに取ってもらう**必要がある。利用規約の雛形に一項目を足すまで、この機能は顧客テナントで有効化しない。

## 1. 画面の流れ（コーチの手の動き）

```
カルテナレッジを開く
   ↓  【🎙 レッスンを記録する】（同意チェックを入れないと押せない）
録音中バッジが画面上部に出たまま、いつもどおり症状を検索・確認項目を見る
   ↓  【■ 記録を止めてコメントを作る】
数十秒で下書きが出る（要約は裏で走る／画面を移動しても消えない）
   ↓
「PGA NOTE に貼るコメント」＋「先生の記録」＋「ナレッジ候補（あれば）」
   ↓  【コピー】→ PGA NOTE へ貼る／【確認して保存】
```

- 録音中も **検索・症状別対処法は使えたまま**であること（これが lesson-os との最大の違い＝現場での使い方）。録音状態は画面遷移で切れない作りにする（lesson-os #201 と同じ扱い）。
- **生徒の指定は任意**。standard プラン（生徒CRMなし）でも成立させる。pro のときだけ生徒に紐づける。

## 2. lesson-os の会話メモとの違い（作り分けの理由）

| | lesson-os 会話メモ | CORTEX 音声メモ（本設計） |
|---|---|---|
| 目的 | その生徒のカルテを埋める | **店の頭脳を太らせる ＋ 貼れるコメントを作る** |
| 必須の紐づけ | 生徒・その日のスイング動画 | **なし**（生徒は任意） |
| 出口 | カルテ・お客様の共有ページ | **PGA NOTE に貼るテキスト**（コピー） |
| AIが参照するもの | そのコーチの過去コメント5件 | `sc_settings.style` ＋ 症状/確認項目/実コメント（RAG） |
| 逆流 | しない | **ナレッジ候補として溜める（本設計の主題）** |

すでに `apps/lesson-os/src/lib/lesson-note-ai.ts` の `matchSymptoms()` が **CORTEX の `sc_symptoms` / `sc_checkpoints` に当てにいっている**。つまり「ナレッジ → レッスン」の配線は動いている。本設計はその逆流を足すもので、ゼロからではない。

## 3. データ設計（migration 想定 / sc_*）

```
sc_voice_notes            録音1本＝1行
  id, company_id, coach_staff_id, student_id(null可), lesson_date
  audio_path, audio_seconds, audio_bytes, audio_deleted_at
  consent_at, consent_by                       -- 同意なしに録音を始められない
  status  draft|uploaded|summarized|saved|failed
  transcript, summary jsonb, body, ai_raw, error
  created_at, updated_at, deleted_at

sc_knowledge_candidates   録音から出た「知識になりそうな断片」
  id, company_id, note_id -> sc_voice_notes
  kind          'append' | 'new_symptom'       -- 既存に足す/新しい症状
  symptom_id    -- append のとき寄せ先
  checkpoint_id -- append のとき寄せ先（あれば）
  proposed jsonb  {name?, title?, cause, fix, drill, client_explanation}
  digest text     -- 趣旨の正規化キー（重複を数えるための指紋）
  hits int default 1, first_seen_on date, last_seen_on date
  status  'collected' | 'queued' | 'adopted' | 'rejected'
  adopted_knowledge_id, decided_by, decided_at
  created_at, updated_at
```

- **ナレッジ本体（`sc_symptoms` / `sc_checkpoints` / `sc_knowledge`）は自動では絶対に書かない。** 書き込みは採用ボタンの中だけ。
- 採用したものは `source='learned'` にする（既存の `seed` / `ai` / `manual` / `import` と区別し、「AIが育てた分」だけ後から数えられるようにする）。
- 却下しても行は消さない。「5回出ているのに採用していない」が見えることに価値がある。

## 4. 昇格の規則（ここが設計の芯）

**毎晩1回のバッチ**が候補を見直す。

1. その日の候補それぞれについて、既存の症状・確認項目に寄せられるかを `lib/jp-search.ts` のあいまい一致で判定する
   - 寄せられる → `kind='append'`（**まずこれを狙う**。新しい症状を増やすより、既存の確認項目に言い回し・ドリルを1つ足すほうが安全）
   - 寄せられない → `kind='new_symptom'`
2. `digest`（趣旨の指紋）が一致する既存候補があれば **`hits` を1つ増やし、`last_seen_on` を更新するだけ**。行は増やさない。
   **`hits` は回数ではなく「出た日数」**（`last_seen_on` と同じ日なら増やさない）。1回のレッスンの中で同じ話が繰り返されるのは普通なので、素の回数では門にならない
3. **`hits >= 3` かつ `first_seen_on <> last_seen_on`（＝別の日にまたがっている）** の候補だけ `status='queued'` に上げる
4. `queued` は設定画面の「ナレッジの提案」に並ぶ。**1タップで採用／却下**

**なぜ回数で門を作るのか**: 「完成度が高いか」をAI自身に採点させると、AIは自分の答案を自分で採点することになる。2026-08-28 の自律進化の検証で、進化したエージェントが**減点していたログのほうを消して満点を取った**実例を確認している。回数は AI が操作できない外側の事実で、しかも「実際のレッスンで繰り返し出た＝この店で本当に使われている言葉」という、堀そのものの意味を持つ。

**なぜ新症状の増殖を止めるのか**: `jp-search` は「伸び上がり／のびあがり／起き上がる」を同じ症状に寄せる作り。そこへ言い換え症状が自動で増えると診断が2つに割れ、どちらも痩せる。現状 GOLF WING 40症状・津 33症状に対し、1日1件の自動追加は半年で元の量を超える。

## 5. 承認の画面（設定 → 「ナレッジの提案」）

1件のカードに出すもの:

- 提案の中身（寄せ先の症状／確認項目、追加する原因・対処・ドリル・生徒向け説明）
- **根拠**: 何回・いつ出たか、元になったレッスンの日付、該当箇所の抜粋
- 【採用】【却下】【文言を直して採用】

一度に出す件数は上限を決める（1日5件まで等）。**押す回数が増えたら設計が間違っている**と考える。

## 6. 共通化（packages への切り出し）

会話メモは2回目なので、`docs/genesis/MODULARIZATION_PLAN.md` の「2回目で切り出す」に従う。

切り出す対象（lesson-os から移す）:
- 録音しながらの逐次アップロード（停止後は最後の数秒だけ送る）
- Gemini への音声直渡し・要約の裏走り・欠損時のフォールバック
- **要約完了で音声を自動削除**する処理（`audio_path=null` ＋ `audio_deleted_at`）
- 同意ゲート（チェックなしでは録音ボタンが押せない・時刻とスタッフを残す）

残すもの（アプリ固有）: プロンプト（lesson-os はコーチの文体／CORTEX は `sc_settings.style` ＋ 症状）、保存先テーブル、画面。

環境変数はすでに `CORTEX_GEMINI_MODEL` を lesson-os が参照しており、片足は共通になっている。

## 7. 同意・規約（外販の前提条件）

自社は店頭掲示と口頭で足りるが、**外販は導入先の店舗ごとに同意の取得が必要**。PGA NOTE の導入施設に広げる前に、次を固める。

- 利用規約の雛形に「レッスン内容の記録」条項（`claude/lesson-os_会話メモ_録音の同意文ドラフト_2026-08-28` の (C) を流用）
- 店頭掲示のPDF雛形を導入キットに同梱
- 導入先ごとに「同意運用を行う」ことを契約書に明記
- **匿名統計データの利用条項**（2026-08-23 に方針決定済み）— 候補の集計を他店に使う場合はここが根拠になるが、**当面はテナントを跨いだ知識の共有はしない**

システム側で既に守れること（lesson-os で実装済み・そのまま移せる）: 同意なしに録音できない／要約後に音声を自動削除／文字起こしはボタン1つで削除／AIは下書きでコーチが確定したものだけが残る／健康状態や私的な話は要約に入れない指示。

## 8. PGA NOTE 補助としての出口

- 主役は **コピーできるテキスト**。診断シートの「お客様への説明をコピー」と同じ導線を、音声メモの結果にも付ける
- PGA NOTE 側への自動投入は **やらない**（相手のシステムに書きに行くと障害の切り分けができなくなる）。貼る手間1回を残す
- 売り文句は「記録が増えるほど、その教室の言葉で書けるようになる」。**candidates の採用件数がそのまま実績の数字になる**ので、`/insights` に「AIが育てた知識 n件」を出す

## 9. フェーズ（V1・V2 は 2026-09-03 に実装済み）

| | 中身 | 判断したいこと |
|---|---|---|
| **V1** | 録音 → コメント生成 → コピー／保存。候補は**溜めるだけで画面に出さない** | 実レッスンで文字起こしと生成がどれだけ使えるか |
| **V2** | 昇格バッチ ＋ 設定の「ナレッジの提案」＋ 採用/却下 | 3回・別日という門が緩いか厳しいか（溜まった候補で後から検証できる） |
| **V3** | `packages/` への切り出し、lesson-os を共通実装に載せ替え | 2本目が動いてから直す |

V1 の時点で候補は溜め始める。あとから門の条件だけ変えて再評価できる。

## 10. まだ決めていないこと

- `digest`（趣旨の指紋）の作り方 — 症状キー＋対処の要点を正規化して作る想定だが、粒度は実データで決める
- 昇格の閾値 3回／別日 は仮。既存の実コメントでシミュレーションしてから確定する
- 録音の単価（Gemini の音声）と、外販時の月額への転嫁
- 生徒の紐づけを standard でも任意で許すか（許すと pro との線引きが曖昧になる）

## 11. 実装（2026-09-03・#207）

V1（録音→コメント）と V2（候補→提案→採用）を同時に入れた。設計からの変更は2つだけ。

- **生徒に紐づけない**（ユーザー指示）。`sc_voice_notes` に `student_id` は無い。standard プランのまま動く。
- **昇格バッチを cron にしなかった。** 判定は純粋な計算で軽いので、録音の要約が終わったその場で回す（`api/voice-note/summarize`）。結果は毎晩回すのと同じで、cron を1本増やさずに済む。

| 置き場 | 役割 |
|---|---|
| `supabase/migrations/0145_cortex_voice_note.sql` | `sc_voice_notes` / `sc_knowledge_candidates` / `cortex-audio` バケット / `sc_knowledge.source` に `learned` |
| `src/lib/candidates.ts` | **純関数**。寄せ先の判定（`placeCandidate`）・指紋（`makeDigest`）・昇格の門（`shouldQueue`）。テストは `tests/swing-cortex-candidates.test.ts` |
| `src/lib/voice-note-ai.ts` | Gemini に音声を直渡し → コメント／先生の記録／**知識の候補**（最大3件） |
| `src/app/api/voice-note/summarize/route.ts` | 要約 → 候補を溜める → 昇格 → 音声を消す。**ナレッジ本体には書かない** |
| `src/app/(main)/voice-bar.tsx` | 録音バー。**layout.tsx に置く**（ページに置くと画面遷移で録音が止まる） |
| `src/app/(main)/note/` | 下書きを直して保存する画面（【記録】タブ） |
| `src/app/(main)/settings/candidate-actions.ts` | **ナレッジ本体に書く唯一の入口**（採用ボタン）。`source='learned'` |
| `src/app/(main)/settings/candidates-client.tsx` | ナレッジの提案（採用／見送り／直して採用） |

残っているユーザー作業: Vercel の swing-cortex に **`GEMINI_API_KEY`**（未設定だと録音は残るが下書きが作られない）、および §7 の同意・規約。
