## 2. 全体アーキテクチャ

全チャネル共通の1本のファネルに載せる。チャネルごとに別システムは作らない。

```
DISCOVER ──→ SCORE ──→ DEMO ──→ OUTREACH ──→ TRACK ──→ DEAL
発見          選定      生成      接触          計測      商談
@yozan/       同左      demo-    @yozan/       @yozan/   demo-sales
prospect              sales裾野  outreach      track     sales-os
（新規①）             拡張       （新規②）     （済）    （済）
                                    ↑
                     @yozan/content（新規③・SNSインバウンド）
                     投稿→LP→問い合わせがこのファネルに合流
```

- パッケージはすべてSupabaseクライアントを引数で受けるアプリ非依存構成（hp-sales-pipeline方針を踏襲）
- 通知はすべて**Genesisホームの判断フィード＋メール**に集約（既存方針どおり）
- 承認が要るものは判断フィードのカード（#100の実行プラン＋文面全文＋修正指示UI）に載せる

## 3. チャネル別設計

### チャネルA: Google Maps → HPが無い/古い事業者（メール・郵送）

1. **発見**: Google Places API（Text Search）でエリア×業種を走査し、`website`フィールドが無い or あってもprospectスコアが低い（SSL無し/非レスポンシブ/更新停止/予約導線無し）事業者を抽出。@yozan/prospectの`gmaps`アダプタとして実装
2. **選定**: 既定計画①のスコアリング（SSL/viewport/最終更新/予約導線/PageSpeed）をそのまま使用
3. **生成**: demo-salesの既存テンプレでデモ自動生成（業種10種）
4. **接触**: 連絡先の実態で2分岐
   - メール公表あり（古いHP持ち）→ @yozan/outreachでメール送信（特定電子メール法3条1項3号の範囲内・下記§5）
   - **HP完全無し=メールも取れないのが普通** → 郵送/電話リストとして出力（デモURLのQR付き提案書1枚。demo-salesの提案書生成を流用）。ここを無理にスクレイピングで埋めない
5. **計測→商談**: track開封→ホットリード→demo-sales商談へ（既存）

### チャネルB: SNS DM → プロゴルファー・インフルエンサー（個人HP営業）

1. **発見**: Instagram/X上でハッシュタグ・肩書き・フォロワー帯から候補化。ただし**ハッシュタグ横断検索を自動化できる公式APIは実質無い**ため、候補リストは「AIがブラウザで収集→psp_prospectsに投入」の半自動（Claude in Chromeでの定期収集タスク）とする
2. **生成**: demo-salesに**新テンプレ「アスリート/インフルエンサー個人サイト」**を追加（プロフィール/戦績/レッスン案内/スポンサー枠/SNS埋込/問い合わせ）。本人の公開プロフィール・投稿から自動で中身を埋める
3. **接触**: **コールドDMは半自動が上限（2026-08-04調査済・確定）**。調査結果:
   - 公式APIで自動DMが許されるのは「相手起点」のみ（コメント・ストーリー返信・キーワードDMへの24時間以内の自動返信、上限200通/時）。**未接触の相手への自動DMは規約上の合法ルートが存在しない**
   - 非公式ブラウザボット（パスワードを渡すツール）が凍結の主因。受信者の通報率0.6%超でも自動審査入り
   - → コールドは半自動、ただし**「コメントしたら自動でデモリンクをDM」型は完全自動が合法**なのでチャネルCの投稿と組み合わせて活用する（例: 投稿に「診断」とコメント→自動DMでリンク送付）
   設計は:
   - AIがターゲット選定＋デモ生成＋DM文面（/d/token リンク入り）まで全自動で用意
   - 判断フィードに「送信キュー」カードで並ぶ → 承認 → **送信タップだけ人間**（1日10〜20件が安全域）
4. **計測**: リンク開封でホットリード（DMは開封率が高いのでここが効く）

### チャネルC: SNSインバウンド → PGA NOTE / SWING CORTEX（本命・資産）

アウトバウンド(A/B)は刈り取り、Cは**畑を育てる**方。今後の主力。

1. **コンテンツエンジン（@yozan/content）**: SWING CORTEXの知識資産（症状→原因→対処、実コメント5,939件由来のメソッド）から、コーチ・ゴルファー向けの投稿を毎日自動生成
   - 例:「右に曲がる本当の原因は◯◯」「コーチが現場で使う説明フレーズ」→ 末尾でSWING CORTEX/PGA NOTEへ誘導
   - 生成→**判断フィードで承認→予約投稿**。AI社員の成果物パイプライン（agent-runner/deliverables「承認しても配信しない」）を配信ありに拡張する形
2. **自動投稿**: Instagram Graph API（ビジネスアカウントの自前投稿は公式に自動化可・凍結リスク無し）。X はAPI有料のため要判断
3. **受け皿LP**: PGA NOTE用・SWING CORTEX用の縦長LP各1枚（sites/frank-golf同様の静的生成）。track計測＋問い合わせフォーム
4. **リード自動投入**: フォーム送信 → sales_osスキーマの`leads`＋福原氏の`tasks`に自動作成（境界はAPI1本。sales_osはスキーマ分離のため直接JOINしない）→ 福原氏の「今日やること」に翌朝出る
5. **週次ファネルレポート**: 投稿数→リーチ→LP閲覧→問い合わせを判断フィードに自動報告

## 5. 法務・リスクの線引き

- **メール**: 特定電子メール法 — アドレスを自ら公表している営業者へは同意なし送信可、ただし「営業お断り」表示先は除外。4条の表示義務（送信者名/住所/配信停止先）をテンプレに常設。送信専用ドメイン＋SPF/DKIM/DMARC＋1日30〜50通ウォームアップ
- **DM**: 自動送信はしない（凍結＝チャネル喪失が最大リスク）。生成と承認までを自動化し送信は人
- **医療系デモ**: 医療広告ガイドライン（体験談・ビフォーアフター写真NG）を継続適用
- **SWING CORTEX外販**: 見せるのはstandard仕様（P4決定: 生徒CRMはpro=自社限定）
